Q28. Construct a DFA over {0,1} that accepts strings ending in 01. Give the
     transition table and trace 1101 and 1010.
--------------------------------------------------------------------------------

>> DFA (Deterministic Finite Automaton)
   Definition : A machine with a finite number of states that reads input one
                symbol at a time and, for each state and symbol, moves to
                exactly ONE next state. It accepts if it ends in a final state.
   Formal     : DFA = (Q, Sigma, delta, q0, F)
   Example    : A lift / traffic signal controller, or a vending machine that
                moves between states as you insert coins.

Idea - each state remembers how much of "01" we have just seen:
   q0 : start / last symbol was 1 that does not help (nothing matched)
   q1 : last symbol was 0          (we have seen "0")
   q2 : last two symbols were 01   (ACCEPT state)

State diagram:

                 1                0
               +---+            +---+
               |   v            |   v
        --> ( q0 ) ---0---> ( q1 ) ---1---> (( q2 ))
               ^                ^              |  |
               |                +------0-------+  |
               +----------------1-----------------+

Transition table:
       State     |  on 0  |  on 1
   --------------+--------+-------
   -> q0 (start) |   q1   |   q0
      q1         |   q1   |   q2
    * q2 (final) |   q1   |   q0

Trace 1101:
   q0 --1--> q0 --1--> q0 --0--> q1 --1--> q2
   Ends in q2 (final)  -> ACCEPTED  (1101 ends in 01)

Trace 1010:
   q0 --1--> q0 --0--> q1 --1--> q2 --0--> q1
   Ends in q1 (not final) -> REJECTED (1010 ends in 10)

Check a few more: 01 -> accept, 001 -> accept, 011 -> reject.

Q29. Compare regular and context-free languages. Write a context-free grammar
     for balanced parentheses and explain why recognizing arbitrarily nested
     parentheses requires more than a finite number of states.
--------------------------------------------------------------------------------

>> Regular language
   Definition : A language that can be described by a regular expression and
                recognized by a finite automaton (no extra memory).
   Example    : 6-digit pincodes, valid identifiers, strings ending in 01.

>> Context-free language (CFL)
   Definition : A language generated by a context-free grammar and recognized
                by a pushdown automaton (a finite automaton plus a stack).
   Example    : Balanced parentheses, a^n b^n, nested if-else blocks in C.

   Feature          | Regular language        | Context-free language
   -----------------+-------------------------+----------------------------
   Chomsky type     | Type 3                  | Type 2
   Described by     | Regular expression,     | Context-free grammar
                    | regular grammar         |
   Machine          | Finite automaton (DFA/  | Pushdown automaton (PDA)
                    | NFA)                    |
   Memory           | Only finite states      | States + a stack
   Can count?       | Only up to a fixed limit| Unbounded nesting / matching
   Example          | (0|1)*01                | a^n b^n, balanced brackets
   Closed under     | Union, intersection,    | Union, concatenation, star;
                    | complement              | NOT intersection/complement
   Use in compiler  | Lexical analyzer        | Parser (syntax analysis)

   Every regular language is context-free, but not every CFL is regular.

>> Context-free grammar (CFG)
   Definition : A set of rules (productions) of the form A -> string, where
                the left side is a single non-terminal, used to generate all
                strings of a language. G = (V, T, P, S).
   Example    : Grammar rules of a programming language in its manual.

CFG for balanced parentheses:
   S -> ( S ) S  |  e          (e = empty string)

   Meaning: a balanced string is either empty, or "(" balanced ")" followed
   by another balanced string.

Derivation of (())():
   S => (S)S
     => ((S)S)S        [inner S -> (S)S]
     => (()S)S         [S -> e]
     => (())S          [S -> e]
     => (())(S)S       [S -> (S)S]
     => (())()S        [S -> e]
     => (())()         [S -> e]

Why a finite number of states is not enough:
   - To check balance you must remember how many "(" are still open, and
     the nesting can be any depth (1, 10, 1000, ...).
   - A DFA with k states can remember only k different situations.
   - Feed it k+1 opening brackets: by the pigeonhole principle, two different
     counts (^i and (^j with i < j) must end in the SAME state.
   - From that state, appending )^i is accepted after (^i, so it is also
     accepted after (^j - but (^j )^i is NOT balanced. Contradiction.
   - So the language is not regular (formally proved by the pumping lemma).
   - A PDA solves it with a stack: push on "(", pop on ")", accept if the
     stack is empty at the end.
   Real-life example: a counter with only 2 digits cannot count 150 people;
   you need memory that can grow - that is the stack.

Q30. Explain the phases of a compiler using x = a + b * c. Show the token
     sequence, a syntax tree, and one possible three-address-code
     representation.
--------------------------------------------------------------------------------

>> Compiler
   Definition : A program that translates the whole source program (e.g. C)
                into target machine code, reporting errors along the way.
   Example    : Like a translator converting a full English book into Telugu
                before anyone reads it.

Phases (analysis = front end, synthesis = back end):

   Source: x = a + b * c
      |
   1. Lexical analysis ............ tokens
   2. Syntax analysis ............. parse / syntax tree
   3. Semantic analysis ........... type-checked tree
   4. Intermediate code generation  three-address code
   5. Code optimization ........... better intermediate code
   6. Code generation ............. assembly / machine code
      |
   Target code
   (Symbol table and error handler are used by ALL phases.)

>> 1. Lexical analysis (scanner)
   Definition : Reads characters and groups them into tokens (meaningful
                words), removing spaces and comments.
   Example    : Like splitting a sentence into words.

   Tokens for x = a + b * c :
      <id,1>  <=>  <id,2>  <+>  <id,3>  <*>  <id,4>
   Symbol table:   1: x    2: a    3: b    4: c

>> 2. Syntax analysis (parser)
   Definition : Checks the token order against the grammar and builds a
                syntax tree.
   Example    : Like checking a sentence's grammar.
   Note       : * has higher precedence than +, so b * c is grouped first.

   Syntax tree:
                =
              /   \
             x     +
                 /   \
                a     *
                    /   \
                   b     c

>> 3. Semantic analysis
   Definition : Checks meaning - variables declared, types compatible - and
                adds type conversions.
   Example    : "The table ate the book" has correct grammar but no meaning.
                If a is int and b, c are float, it inserts inttofloat(a).

>> 4. Intermediate code generation
   Definition : Produces simple machine-independent code, usually
                three-address code (at most one operator on the right side).
   Three-address code:
       t1 = b * c
       t2 = a + t1
       x  = t2

   Same code as quadruples:
       op | arg1 | arg2 | result
       ---+------+------+-------
       *  |  b   |  c   |  t1
       +  |  a   |  t1  |  t2
       =  |  t2  |      |  x

>> 5. Code optimization
   Definition : Improves the intermediate code to run faster or use less
                memory without changing the result.
   Example    : Remove the extra copy:
                   t1 = b * c
                   x  = a + t1

>> 6. Code generation
   Definition : Converts the optimized code into target machine instructions
                and allocates registers.
       LOAD  R1, b
       MUL   R1, c       ; R1 = b * c
       ADD   R1, a       ; R1 = a + b * c
       STORE x, R1

Q31. Explain instruction pipelining. Describe structural, data, and control
     hazards, and illustrate how forwarding can resolve a data hazard.
--------------------------------------------------------------------------------

>> Instruction pipelining
   Definition : Splitting instruction execution into stages and overlapping
                them, so a new instruction starts every clock cycle while
                others are still finishing.
   Example    : Laundry - while load 1 is drying, load 2 is washing, and load
                3 is being folded. Each load still takes the same time, but
                more loads finish per hour (higher throughput).

Classic 5 stages:
   IF  - Instruction Fetch      ID  - Instruction Decode / read registers
   EX  - Execute (ALU)          MEM - Memory access     WB - Write Back

   Cycle :  1    2    3    4    5    6    7    8
   I1    :  IF   ID   EX   MEM  WB
   I2    :       IF   ID   EX   MEM  WB
   I3    :            IF   ID   EX   MEM  WB
   I4    :                 IF   ID   EX   MEM  WB

   Without pipelining: 4 instructions x 5 cycles = 20 cycles.
   With pipelining   : 5 + (4 - 1) = 8 cycles.
   Formula: time = k + (n - 1) cycles for n instructions, k stages;
            ideal speed-up approaches k.

>> Pipeline hazard
   Definition : A situation that stops the next instruction from executing in
                its planned cycle, causing stalls (bubbles).

>> Structural hazard
   Definition : Two instructions need the same hardware resource in the same
                cycle.
   Example    : One memory port - I1 is reading data (MEM) while I4 wants to
                fetch an instruction (IF). Like two people needing the only
                washing machine at once.
   Fix        : Separate instruction and data caches (Harvard style),
                duplicate resources, or stall.

>> Data hazard (RAW - Read After Write)
   Definition : An instruction needs a result that a previous instruction has
                not yet written back.
   Example    : ADD R1, R2, R3   ; R1 = R2 + R3
                SUB R4, R1, R5   ; needs the new R1
                Like trying to fold clothes that are still in the dryer.
   Fix        : Forwarding (bypassing), stalls, or compiler reordering.

>> Control hazard (branch hazard)
   Definition : After a branch/jump, the CPU does not yet know which
                instruction to fetch next.
   Example    : if (x > 0) ... - the next instruction depends on the result.
                Like a road fork where you don't know which way to go until
                you read the sign.
   Fix        : Stall, branch prediction (guess and flush if wrong), delayed
                branch, computing the branch early in ID.

>> Forwarding (bypassing)
   Definition : Sending an ALU result directly from a pipeline register to
                the next instruction's ALU input, instead of waiting for it
                to be written to the register file.
   Example    : Handing the dried clothes directly to the folder instead of
                first putting them back in the cupboard.

   Without forwarding (2 stall cycles):
   Cycle            :  1    2    3    4    5    6    7    8
   ADD R1,R2,R3     :  IF   ID   EX   MEM  WB
   SUB R4,R1,R5     :       IF   --   --   ID   EX   MEM  WB
                    (SUB waits until ADD writes R1 in cycle 5)

   With forwarding (no stall):
   Cycle            :  1    2    3    4    5    6
   ADD R1,R2,R3     :  IF   ID   EX   MEM  WB
                                  |
                                  +--> R1 value from EX/MEM register
                                       |
   SUB R4,R1,R5     :       IF   ID   EX   MEM  WB
   ADD computes R1 at the end of cycle 3; it is forwarded into SUB's EX in
   cycle 4 - no waiting.

   Limitation: load-use hazard -
       LW  R1, 0(R2)
       ADD R3, R1, R4
   The loaded value is ready only after MEM, so even with forwarding one
   stall is needed (or the compiler places an independent instruction there).

Q32. Explain cache memory, temporal locality, and spatial locality. Compare
     sequential array traversal with pointer-based linked-list traversal from
     a cache perspective.
--------------------------------------------------------------------------------

>> Cache memory
   Definition : A small, very fast memory between the CPU and main memory
                (RAM) that keeps copies of recently or frequently used data.
   Example    : Keeping the books you use daily on your desk instead of
                walking to the library each time.

>> Cache hit / miss
   Definition : Hit = data found in cache (fast). Miss = not found, so it must
                be fetched from RAM (slow).
   Formula    : Average access time = hit time + miss rate x miss penalty
   Example    : 1 ns + 0.05 x 100 ns = 6 ns (vs 100 ns with no cache).

>> Cache line (block)
   Definition : Data moves between RAM and cache in fixed-size blocks
                (typically 64 bytes), not one byte at a time.
   Example    : When you fetch one book, you bring the whole shelf section
                near it.
   Levels     : L1 (smallest, fastest) -> L2 -> L3 -> RAM.

>> Temporal locality
   Definition : If a data item is used now, it is likely to be used again
                soon.
   Example    : Loop variables i and sum are used in every iteration; your
                most-used apps stay in the recent-apps list.

>> Spatial locality
   Definition : If one memory address is used, nearby addresses are likely to
                be used soon.
   Example    : Reading a book page after page; reading arr[0], arr[1],
                arr[2] ...

Array vs linked list traversal:

   Array (sequential traversal)
     - Elements are stored side by side in memory.
     - One 64-byte cache line holds 16 ints (4 bytes each), so one miss
       brings 16 elements -> about 1 miss per 16 accesses.
     - The hardware prefetcher sees the regular pattern and loads the next
       lines early.
     - Excellent spatial locality.

   Linked list (pointer traversal)
     - Nodes are scattered anywhere in the heap.
     - Each node may be in a different cache line -> possibly 1 miss per
       node.
     - "Pointer chasing": the next address is known only after the current
       node is loaded, so the prefetcher cannot help.
     - Extra memory for pointers means fewer useful values per cache line.
     - Poor spatial locality.

   Feature             | Array                  | Linked list
   --------------------+------------------------+--------------------------
   Memory layout       | Contiguous             | Scattered nodes
   Spatial locality    | Excellent              | Poor
   Cache misses        | ~1 per cache line      | ~1 per node (worst case)
   Prefetching         | Works well             | Mostly useless
   Big-O traversal     | O(n)                   | O(n)
   Real speed          | Often several times    | Slower
                       | faster                 |

   Real-life example: reading a novel page by page (array) vs a treasure hunt
   where each clue tells you which part of the city to go to next (linked
   list).
   Key point: both are O(n), but Big-O hides cache effects - that is why
   arrays / dynamic arrays (Python list, C++ vector) are usually preferred
   for traversal-heavy work.
