Creating objects __init__ · arguments · defaults

01Can __init__ return a value?

  • No. __init__ must return None.
  • The object already exists. __init__ only fills it in.
  • Returning anything else, like 10, raises TypeError.
class Phone:
    def __init__(self, model):
        self.model = model
        return 10          # not allowed

Phone("A1")
# TypeError: __init__() should return None, not 'int'
Real life · New phoneWhen you set up a new phone, you choose the language and Wi-Fi. Setup doesn't hand you a second phone. The phone already exists.

02How do you know which arguments to pass when creating an object or calling a method?

  • Look at the parameters of __init__ or the method.
  • Pass a value for each required parameter.
  • Parameters with defaults are optional.
  • Python supplies self automatically.
  • Child class: Python runs the child's __init__ if it has one, otherwise the parent's.
class Rectangle:
    def __init__(self, length):
        self.length = length

    def area(self, width):
        return self.length * width

r = Rectangle(10)      # pass length
print(r.area(5))       # 50: pass width, self = r
Real life · Form, areaA form marks which fields are required and which are optional. Your name (self) is already filled in. To find a room's area, you give only the width, because the room already knows its length.

03How do you set a default value in __init__, and how do you override it?

  • Write the default with =, like size="medium".
  • Leave the argument out to use the default.
  • Pass a value to override it for that object only.
  • Parameters with defaults come after required ones.
class Pizza:
    def __init__(self, size="medium"):
        self.size = size

print(Pizza().size)          # medium
print(Pizza("large").size)   # large
Real life · Pizza sizeYou get a medium pizza unless you ask for something else. Ask for a large and you get a large. The next customer still gets a medium.

self and instance keyword? · difference · scope

04Is self a reserved keyword or a naming convention?

  • A naming convention, not a keyword.
  • The first parameter of a method receives the object, whatever you call it.
  • Always name it self so others can read your code.
class Greeter:
    def hello(me):       # works, but don't do this
        return "Good morning"

print(Greeter().hello())  # Good morning
Real life · "Good morning"Saying "Good morning" is a habit everyone follows, not a law. You could say something else and it would still work, but people would find it odd.

05What is the difference between self and an instance?

  • They are the same object.
  • self is the name used inside the class.
  • The instance name, like car, is used outside the class.
class Car:
    def __init__(self, name):
        self.name = name     # inside: self

    def me(self):
        return self

car = Car("Swift")          # outside: car
print(car.me() is car)     # True
Real life · Car and nameOther people call you by your name, like the instance car. You call yourself "I", like self. It's the same person.

06Where can you use self and the instance name (scope)?

  • self exists only inside methods.
  • self.x is stored on the object and every method can use it.
  • A plain x is a local variable and disappears when the method ends.
  • Use the instance name outside, after you create the object.
class Car:
    def __init__(self, name):
        self.name = name   # on the object
        speed = 0          # local, gone after __init__

    def show(self):
        return self.name   # OK; using speed here fails

car = Car("Swift")
print(car.name)   # Swift
Real life · Your roomAt home you say "my room" (self). Outside, people say "Asha's room" (the instance). A sticky note you throw away after one task is a local variable.

Attributes and methods lists · shared data · calling · method types

07How do you add an element to a list stored on an instance?

  • Create the list in __init__ so each object gets its own.
  • Inside the class, use self.members.append(x).
  • Outside the class, use t.members.append(x).
class Team:
    def __init__(self):
        self.members = []

    def add(self, name):
        self.members.append(name)

t = Team()
t.add("Asha")
print(t.members)   # ['Asha']
Real life · Your own notebookEach person in the office has their own notebook. When you write in yours, nobody else's changes.

08Is a mutable class attribute shared?

  • Yes. A list or dict in the class body belongs to the class.
  • Every object sees the same single copy.
  • For a separate copy per object, create it in __init__.
class Team:
    members = []         # shared by all

a, b = Team(), Team()
a.members.append("Asha")
print(b.members)   # ['Asha']: b sees it too
Real life · Office whiteboardThe office whiteboard is shared. Anything one person writes on it, everyone sees.

09What are the different ways to call an instance method?

  • 1. Through the object: f.call()
  • 2. Through the class, passing the object: Friend.call(f)
  • 3. By name with getattr(f, "call")()
  • 4. Inside the class with self.call()
  • 5. From a child class with super().call()
class Friend:
    def call(self):
        return "ringing"
    def remind(self):
        return self.call()          # 4

class BestFriend(Friend):
    def call(self):
        return super().call()       # 5

f = Friend()
f.call()                 # 1
Friend.call(f)           # 2
getattr(f, "call")()     # 3
# all return 'ringing'
Real life · Reaching a friendYou can reach the same friend by phone, email, a message, or a visit to their home. There are many routes, but it's always the same friend.

10What is the difference between instance, class, and static methods?

  • Instance method: gets self and uses one object's data.
  • Class method: has @classmethod, gets cls, and uses data shared by all objects.
  • Static method: has @staticmethod and gets neither. It's a helper function grouped with the class.
class Pizza:
    price_per_inch = 50

    def __init__(self, inches):
        self.inches = inches

    def price(self):                # instance
        return self.inches * self.price_per_inch

    @classmethod
    def set_rate(cls, rate):        # class
        cls.price_per_inch = rate

    @staticmethod
    def to_cm(inches):              # static
        return inches * 2.54

print(Pizza(10).price())   # 500
Pizza.set_rate(60)
print(Pizza(10).price())   # 600
print(Pizza.to_cm(10))     # 25.4
Real life · Pizza shopThe price of this pizza is an instance method. The menu rate for every pizza is a class method. An inch-to-cm converter on the wall needs no pizza at all, like a static method.

11Can a class method read and update attributes stored on the class?

  • Yes. Through cls it reads and changes class attributes.
  • Every object sees the new value, unless an object has its own value with the same name.
class Student:
    school = "City School"

    @classmethod
    def rename_school(cls, new):
        cls.school = new

a = Student()
Student.rename_school("Green Valley")
print(a.school)   # Green Valley
Real life · Change school nameWhen the principal renames the school, every student's ID card shows the new name. Nobody updates each card one by one.

Inheritance subclass · parent __init__ · is-a · super() · MRO

12How do you declare a subclass in Python?

  • Syntax: class ChildClass(ParentClass):
  • Put the parent class name in brackets after the child's name.
  • The child gets every parent method and can add or replace methods.
class Animal:
    def eat(self):
        return "eating"

class Dog(Animal):      # Animal is the parent
    def bark(self):
        return "woof"

print(Dog().eat())    # eating: from the parent
Real life · A dog is an animalA dog is an animal, so it eats like all animals. It also barks, which is its own extra skill.

13Can a child class use its parent's __init__ if it doesn't define one?

  • Yes. Python looks up __init__ in the parent.
  • Pass the parent's arguments when you create the child.
  • If the child defines its own __init__, call super().__init__(...) to keep the parent's setup.
class Shop:
    def __init__(self, name):
        self.name = name

class Branch(Shop):
    pass

print(Branch("Pune").name)   # Pune
Real life · New shop branchA new branch follows the head office's opening rules unless it writes its own rules.

14What is an is-a relationship, and why use it?

  • Use inheritance only when the child is a kind of parent: a Dog is an Animal.
  • If it has a part, like a Car has an Engine, use composition instead.
  • Benefit: you reuse the parent's code, and isinstance checks work.
class Animal: pass
class Dog(Animal): pass     # is-a

class Engine: pass
class Car:
    def __init__(self):
        self.engine = Engine()  # has-a

print(isinstance(Dog(), Animal))  # True
Real life · ManagerA manager is an employee, so the manager gets every employee benefit. A manager has a laptop, but a manager is not a laptop.

15What are the different forms of super()?

  • 1. Parent setup: super().__init__(name)
  • 2. Parent method: super().greet()
  • 3. Parent class attribute: super().kind
  • 4. Parent class method: super().describe() inside a @classmethod
class Parent:
    kind = "parent"
    def __init__(self, name): self.name = name
    def greet(self): return "hello"
    @classmethod
    def describe(cls): return f"class {cls.__name__}"

class Child(Parent):
    def __init__(self, name, age):
        super().__init__(name)             # 1
        self.age = age
    def greet(self):
        return super().greet() + "!"     # 2
    def info(self):
        return super().kind               # 3
    @classmethod
    def describe(cls):
        return super().describe() + " (child)"  # 4

c = Child("Asha", 21)
print(c.greet())          # hello!
print(c.info())           # parent
print(Child.describe())   # class Child (child)
Real life · FamilyYou move into the family house (setup), cook grandma's recipe with your own twist (method), keep the family surname (class attribute), and follow the family traditions (class method).

16What are multiple inheritance, MRO, and mixins?

  • Multiple inheritance: a class with more than one parent, like class D(B, C).
  • MRO (method resolution order): the order Python searches. It goes left to right, and a shared parent comes last. See it with D.__mro__.
  • Mixin: a small class that adds one feature and isn't meant to be used alone.
class A:
    def hi(self): return "A"
class B(A):
    def hi(self): return "B"
class C(A):
    def hi(self): return "C"
class D(B, C): pass

print(D().hi())   # B
print([k.__name__ for k in D.__mro__])
# ['D', 'B', 'C', 'A', 'object']

import json
class JsonMixin:
    def to_json(self):
        return json.dumps(self.__dict__)

class User(JsonMixin):
    def __init__(self, name): self.name = name

print(User("Asha").to_json())   # {"name": "Asha"}
Real life · Help desk and phone add-onsMRO is like a help-desk queue: you ask the first parent you listed, then the next, and the shared grandparent last. A mixin is like a phone cover or charger: it adds one feature to any phone.
